# 网站图标：提取、清晰度与统一显示

适用版本：v0.3.2。图标是独立的基础能力，网站卡片、文件夹预览和搜索引擎共享提取与缓存。自动缓存不进入桌面/WebDAV；用户明确选择的原图地址或本机图片属于卡片配置，会随备份同步。

## 这次解决的具体问题

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 小 favicon 放大后模糊 | 16/32 像素用于 74 CSS 像素，高密度屏幕需求更高 | 根据显示尺寸 × devicePixelRatio 计算目标，比较真实解码宽高，不用 CSS 放大冒充高清 |
| 明明存在大图却一直显示旧小图 | 优选地址缓存和失败冷却压住了新来源 | 已核验且足够尺寸的新候选可替代陈旧低清优选；低清回退在新图加载期间保持可见 |
| 图标形状忽方忽长、文件夹预览变椭圆 | 图片自身比例不同，以及不同尺寸卡片继承了互相冲突的样式 | 图标显示区域统一为正方形，固定宽高、圆角与 contain；组件拥有独立圆角，不继承网站形状 |
| SPA 首页太大无法解析 | 原先按整页 Content-Length 拒绝读取 | 流式读取有限 head，遇到 head 结束或 body 开始即取消剩余正文；仍受总字节和超时上限约束 |
| ICO 有多张图，只用到小帧 | 容器内帧尺寸各异，直接 img 加载的选择不总符合桌面需求 | 网络允许时解析 ICO 目录，选择真实原生帧，再以原生尺寸解码为本机 PNG；不做超分辨率伪装 |
| 网页跨域看不到网站声明 | GitHub Pages 必须遵循目标站点 CORS | 常用站点补充经核验的首方/声明 CDN 地址。未知站点在权限允许时读取元数据，受限时保留图片或文字回退，不使用代理绕过限制 |

## 正常显示流程

1. 渲染惰性 `.site-visual`，先保留文字/Emoji 回退。
2. 合并本站已缓存声明、已核验的首方图标目录、常规站点图标路径和扩展浏览器 favicon 回退。
3. SVG 与位图声明参与排序；位图优先选择满足目标的合适尺寸，实际解码尺寸会覆盖夸大的声明。`sizes="any"` 本身不能把位图变成矢量。
4. 图片解码成功后记录实际尺寸，适配当前显示区域。足够清晰即停止探测；较差结果不能覆盖更好的已显示图片。
5. 图像不足时，有限尝试更好候选；若“自动补充高清图标”开启，可进一步尝试 ICO 原生帧和公开 head/同源 Manifest。自动流程不弹出权限窗口。元数据读取失败不会阻断网站使用。
6. “获取图标”由用户主动触发，可重试并在扩展中按该站点申请权限。编辑表单列出最多 12 个候选，只有解码成功才允许点选，标明实际尺寸 / SVG，鼠标悬停查看源地址。显式枚举还会读取同源 Manifest，即使 HTML 中已经有足够清晰的图标，避免漏掉另一种原生样式。

当前图像请求共享 4 个并发槽，元数据补充共享 2 个槽。图像单请求超时 8 秒、候选最多 12；常规升级最多 3 个，补充元数据后的新候选最多 3 个。head 读取上限 384 KiB、Manifest 上限 128 KiB、元数据操作总期限 8 秒。ICO 文件上限 1 MiB、帧数最多 64、操作约 3.5 秒，原生帧不超过 256×256。目标像素需求有 256 上限，避免无限追求大尺寸资源。

这不是“每打开一页就抓取所有网站”：有效缓存、足够尺寸、失败退避与离开分组时的作废会减少请求。已经打开的共享元数据请求有有限期限，旧回包不得写回已卸载的卡片。

## 用户选择与持久化

两段式编辑器首先显示网址 / 名称，再显示当前图标、文字图标、发现的原站候选与上传入口。读取候选不会改名、改图或写入桌面；点击候选只改变表单草稿，保存后生效。取消、关闭、更改网址或被替换的表单会使旧异步结果作废。

`iconMode` 仍为 `auto` / `text`。新增可选 `iconUrl`：缺失表示继续自动选择；已选择的 HTTPS 图像 URL 或重新编码后的静态 `data:` 图像具有最高优先级。选择属于单张卡片，不更新同域名的全局自动优选缓存。故意选择低分辨率图标时不会偷偷换成另一个品牌样式；所选源后来失效则文字回退，重新编辑即可更换。

网页只获取原站或其声明的 CDN；常规 `/favicon.svg` 等路径是候选，不把未加载的猜测地址标为已确认。原站声明可能含多个尺寸但同一图案，也可能只有一张可用图片。位图实际尺寸来自浏览器解码，不靠 `sizes` 声明或缩放声称高清；SVG 可缩放并不保证其内部没有嵌入低清位图。

上传沿用 `avatar.js` 的有界静态图像处理：PNG/JPEG/WebP、输入不超过 4 MiB，中心裁切 256×256 后重新编码，保存数据不超过 256 KiB。不是原文件原样嵌入；拒绝 SVG 上传、内网地址、凭据 URL 和无效 data URL。`src/icon-selection.js` 集中校验，`core.js` 再校验导入，单份备份仍不能超过 6 MiB。

## 外观设置与入口

点击侧栏底部四格图标，或“设置 → 图标”。大小 48–120px，圆角 0–48px（不超过当前半径），不透明度 20–100%，间距 8–40px，名称字号 10–20px；名称显示与颜色分别可调。

“统一圆角正方形”统一的是显示框，不强行扭曲品牌标志。默认衬底随深浅主题变化；可改透明衬底或选择原始轮廓。源文件本身有白底时原样保留，不进行可能误删白色文字的自动抠图。搜索引擎标志保持透明容器，不添加统一底板。

组件 2×2、4×2 按真实网格比例呈现，其 20px 圆角不再受图标圆角设置影响。名称字号增加时预留区域同步增加，不把大文字挤进固定的 18px 行高。

## 安全、缓存与网络差异

仅处理规范化的公开 HTTPS 来源，不使用内网/IP/凭据 URL、自定义端口、跨源重定向作为提取入口。去除页面查询与片段，省略 Cookie/认证/Referer，不请求搜索引擎结果页。HTML 通过惰性解析器读取声明，不执行其中脚本，不注入抓取的 HTML；SVG 仅作为图片，不以可执行文档嵌入。

`qiye.favicons.local.v1` 保存候选、质量测量与来源，7 天、最多 200 页；元数据失败退避 10 分钟，图片失败退避 5 分钟，同等或更小需求的普通升级有 24 小时冷却。主动提取可以重试。

`qiye.icon-artwork.v1` 是 ICO 帧解码后的本机 PNG 缓存，7 天、最多 16 张、约 2.4 MB 文本容量。两个缓存都不进入桌面 JSON 或 WebDAV。缓存写入失败只影响下次命中，不清除收藏。字体、用户头像和图标缓存互相独立。

扩展可在“获取图标”时按源请求读取权限；自动补充只使用已有权限。网页受 CORS 与反盗链限制，可能显示图片但无法读其文件字节。这种情况下不会使用转发代理，不把收藏提交给第三方 favicon 聚合服务。

## 核验与维护

`src/site-icon-catalog.js` 保存 2026-10-12 实际核验的首方声明元数据（不复制图标图片）。Google 的 128px 首方图片、Figma 的 SVG/192/256 PNG、GitHub 的 SVG/512 图等作为常用来源补充；来源变更会失败回退，而不是永久假定其有效。核验记录见 `docs/SOURCE-AUDIT.json` 和对应 Actions。

新增目录条目必须记录实际 head/Manifest 或首方品牌素材来源，验证 HTTPS、返回类型和原生尺寸；不能从第三方搜索缩略图猜地址，也不能仅把同一低清 URL 的声明尺寸改大。运行 `npm test`、浏览器回归，再检查正式页面的自然宽高与 `data-icon-quality`。

剩余限制：原站只提供小图、需要登录、反盗链、网络不可达或跨域策略不允许时，仍可能低清或显示文字。网站所称的 SVG 也可能只是内嵌低清位图；代码不将其视作内容质量的绝对保证。此版本支持有界本机静态图片上传，不提供远端图标商店或人工绘制品牌替代图。
