# v0.8.0 审阅与布局调整

## 本轮问题与修复

| 问题 | 修复 |
| --- | --- |
| 图标标签预留高度进入网格单元，所有组件偏大 | 用 `gridMetrics` / `widgetDimensions` 统一桌面与目录几何，标签位于间隙 |
| 目录只有固定尺寸预览，选择尺寸不会改变展示 | 每张卡片独立保存预览尺寸，左右循环、可聚焦尺寸圆点、当前尺寸说明，添加使用该尺寸 |
| 窗口百分比通过 CSS zoom 放大一切 | 删除 dialogScale；windowSize 只控制窗口空间，容器查询重新分栏，字体与控件保持原尺寸 |
| 小组件仅放大或统一显示图标 | 紧凑摘要区分方形、竖版与横版；大卡片使用分栏。宽倒数日增加目标日期，窄版数字与单位分行 |
| 深色下拉框出现白底白字，紧凑便签固定黄色 | 原生 option / optgroup 使用明确的主题颜色；组件遵循各自的深浅语义变量 |
| 时间和侧栏有分散的主题色开关 | 一个 useThemeColor 开关；主页面和收藏弹窗共用 themeTokens，按钮文字按背景亮度选择黑/白 |
| 外部组件的 1×1 被宿主替换，无法自行设计 | API v3 在所有声明尺寸执行真实渲染与生命周期，示例提供可操作的紧凑计数器 |

## 参考尺寸

2026-10-14 读取 [iTab 官方网页版](https://go.itab.link/) 的公开 DOM / 计算样式：

- 1440×900 视口：图标单元 60 px，横纵间距 30 px；2×2 为 150×150，4×2 为 330×150。时间字号 70 px，搜索框 600×46 px，时间顶部 54 px，搜索顶部约 180 px。
- 1280×720 视口：单元约 56.889 px、间距约 28.444 px；2×2 约 142.222 px，4×2 约 312.889 px。时间顶部约 21.6 px。

栖页采用这些默认尺寸和桌面比例，不复制对方资源或私有接口。窄屏最低保持 80% 网格比例以保留可操作面积，可用列数不足时限制横向跨度。用户改变字号、间距、窗口、导航或浏览器缩放后，最终像素自然不同。默认日历窗口为 980×640 CSS px，125% 分配为 1225×800，始终受视口边界限制。

## 模块边界

- `widget-sizes.js`：尺寸契约、单元和卡片几何。
- `window-layout.js`：窗口空间和视口限制，取代旧的整体缩放模块。
- `widget-catalog.js`：无副作用预览和独立选择，不挂载插件、不请求天气或图库。
- `widget-summary.js`：紧凑布局；实时数据仍由 widgets 的统一刷新入口提供。
- `theme.js` / `theme.css`：系统主题、全局主题色、按钮前景色、表单及原生菜单配色。
- `widget-compact.css`：根据 data-display-size 进行信息重排；桌面和静态目录使用同一套布局。

当前采用 schema 5 / Widget API 3。删除分散主题开关与 dialogScale，不做数据迁移或旧接口兼容。旧存储键不读取，也不删除。

## 验证范围

Node 测试覆盖精确默认几何、窄屏边界、窗口预设、自动主题、按钮文字对比选择及目录尺寸契约。浏览器新增 presentation 套件，覆盖中英文、深浅主题、14 个组件的五种尺寸、按钮边界、各卡片独立预览、循环切换、添加尺寸、窗口字体保持、原生菜单配色和键盘选择；源码和单文件网页都执行。原有日历、备忘录草稿、天气、拖拽、编辑器、插件生命周期和解压扩展检查保留。

具体结果见 [QA.md](QA.md)。网上天气、图库可用性和硬件性能不由受控响应测试保证；第三方市场仍是文档和模块接入规范，没有远程脚本安装服务。
