# v0.4.0 代码审阅与改进

审阅对象是本地 v0.3.3 源码，改进日期为 2026-10-13。涉及状态边界、小组件、弹窗、预览构建和 CI；远程发布与部署状态以对应提交的 Actions 记录为准。

## 已修复

| 优先级 | 原问题与影响 | 本轮处理 |
| --- | --- | --- |
| P1 | 同类便签、待办、习惯和专注共享顶层状态；新增/复制卡片后编辑会影响其他卡片 | 所有卡片使用独立 `item.data`，删除顶层共享内容；备份与同步校验覆盖每个实例 |
| P1 | 发布仅有 Actions artifact，没有面向用户的 Release 或精简安装包 | 新版本 main push / 匹配标签触发，测试后发布扩展、源码、预览与校验文件；草稿阶段保证附件传完才正式发布 |
| P2 | 文字比例无法缩放选项窗口；直接放大窗口会使关闭/保存按钮超出视口 | 独立 75–150% 缩放，按实际缩放计算视口限制，窄屏顶部导航、内容滚动、恢复默认和持久化 |
| P2 | 组件目录、类型白名单、校验分散，新组件需要修改多个宿主分支 | 统一 registry；开放打包模块的定义、配置表单、保存及生命周期接口，提供完整示例 |
| P2 | 内置实例数据和旧共享数据容易出现两套校验规则 | 提取 `validation.js` 和 `widget-data.js`，只保留当前实例结构的一套校验 |
| P2 | 壁纸卡片已改为打开图库，仍保留旧浏览器缓存、订阅、图片事件和 apply 分支 | 删除不可达旧逻辑，统一通过现有壁纸中心处理 |
| P2 | 预览构建依赖人工维护模块列表，新增组件容易遗漏或顺序错误 | 自动解析具名相对导入并按依赖顺序打包，拒绝循环依赖和不支持的模块语法 |
| P2 | 旧备份允许小组件采用 1×1 / 2×1，内容会被挤坏 | 直接拒绝不支持的尺寸；推荐尺寸仅在新建时使用 |
| P3 | 壁纸占位作者文字出现在桌面，图库重复展示解释性提示 | 删除占位作者和重复提示；真实图片来源/许可保留在预览，桌面作者显示可开关 |
| P3 | 组件目录只能逐个浏览，添加后才能改尺寸 | 名称/用途搜索、无结果提示、添加前选择尺寸 |
| P3 | 页面版本号重复硬编码 | 从 manifest 生成版本模块，发布检查 package/manifest 一致性 |

按项目尚未正式推出的约定，本轮同时删除旧设置补齐、图标模式迁移、图标缓存 v1 读取及共享内容回退。统一使用完整的 schema 2 和独立存储键，不提供历史格式导入器；创建默认值与校验已有数据分开。

## 与 iTab 的交互参考

参考 [iTab 官方公开介绍](https://www.itab.link/) 的卡片小组件、可选尺寸、网站收藏、极简模式和壁纸使用方式。项目已经具备其中多数基础能力；本轮重点完善“查找组件 → 选择尺寸 → 独立配置”的操作过程，以及不同屏幕下选项窗口的可用性，没有复制其私有接口、素材或备份格式。

保留免栖页账号、本机保存和自有 WebDAV。新组件 API 是代码集成接口，暂未实现动态插件商店、第三方脚本沙箱或权限隔离；接口文档明确这一边界。

## 后续仍值得处理的技术债

| 建议顺序 | 现状 | 可独立推进的工作 |
| --- | --- | --- |
| 1 | `app.js` 仍集中处理设置、收藏表单、菜单和桌面状态 | 按“设置编辑器 / 网站编辑器 / 桌面命令”分模块，先维持公共状态与保存队列语义，逐步替换基于源码提取的旧测试 |
| 2 | styles、refinements、desktop、dialogs 存在历史覆盖层 | 逐个界面合并样式归属，配合深浅色和尺寸截图回归；不一次性删除所有旧规则 |
| 3 | 组件内部列表仍通过 HTML 重建，编辑大量待办时有改进空间 | 用稳定 ID 更新变动的条目，保留键盘焦点与输入光标 |
| 4 | 真实外部服务、扩展授权、触屏尚需设备与服务验收 | 按 QA 分别测试 Chrome/Edge 安装版、真实 WebDAV 冲突、权限申请与触屏拖动 |

本轮保留许可头、边界说明和解释非显然行为的代码注释，删除冗余界面文案与不可达逻辑，不将“删除所有注释”当作优化。完整验证范围见 [QA.md](QA.md)，发布操作见 [RELEASES.md](RELEASES.md)。
